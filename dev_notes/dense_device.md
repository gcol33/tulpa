# Dense device operations

`device::DenseFactor` supplies factorization, log determinant, symmetric solves,
and triangular solves through CPU Eigen LLT and runtime-loaded CUDA. It accepts
a host lower triangle, a covariance generated from retained time values, or a
projected precision assembled from a retained projector. The Newton and Gibbs
drivers call this contract with their matrix and numerical conventions.

The implementation uses the existing `Context`, `Lease`, `Buffer`, `Status`,
operation registry, and fit policy. The registry lists every capability an
operation needs. Automatic selection requires all of them; a forced request
reports a missing capability. No CUDA library is linked into the package DLL.

## Matrices and workspace

Host matrix inputs declare their layout. The dense factor reads the lower
triangle and uses column-major storage internally. cuSOLVER `Dpotrf` reports
non-positive-definiteness through its per-matrix information value, which lets
the existing Newton conditioning policy choose its next diagonal load. Runtime
and argument errors go through `Status` and the fit's first-failure record.
`Dpotrs` solves against the retained factor; cuBLAS `Dtrsm` supplies lower and
transposed-lower solves. Log determinants use the positive factor diagonal.

The temporal covariance formula is the template in
`inst/device/dense_covariance.cu`. Host scalar, arena, directional-derivative,
and NVRTC code use that formula. A CUDA evaluation uploads time values when
they change and generates the covariance on the device. Its nugget and the
exponential bounds are arguments computed from the host's shared conventions.
The Ornstein-Uhlenbeck path continues to read `ar1_one_minus_rho2`; the NNGP
variance floor continues to come from its existing shared header.

Projected RSR conditionals retain the projector and form `P' W P` with cuBLAS.
The precision is factored in the product's device buffer. The ICAR prior matrix
is retained separately from its changing precision multiplier and constant
augmentation. The NNGP prior is uploaded when its assembled values change.
Only the changing residual and weight vectors need their usual transfers.

`DenseBasis` retains immutable bases by identity within a fit policy. Mutable
bases are compared by value before reusing their device copy. Per-worker Newton
scratch owns its basis workspace. The spec and joint scatter paths share the
weighted products and precomputed basis fields, including row amplitudes and
signed curvature. HSGP fields use `Dgemv`; nonnegative weighted
Gram products use `Dsyrk`; signed weighted products and cross-products use
`Dgemm`. Signed Newton curvature is retained. Output matrices needed by host
scatter are downloaded. A newly assembled host Hessian is uploaded for a forced
dense CUDA solve; its automatic gate includes that cost.

Process-owned workspaces are indexed by thread identity. A constant-initialized
thread-local pointer locates each workspace. Their owning container is destroyed
before the shared device context, so its allocations remain valid during cleanup.

## Derivatives

The shared Cholesky pullback uses

`bar(K) = L^-T sym(Phi(L' bar(L))) L^-1`,

where `Phi` keeps the lower triangle and halves its diagonal. CPU and CUDA
implementations use matrix products and triangular solves. The operation has
its own measured gate. Temporal covariance tangents are generated by scalar
directional derivatives of the shared covariance formula. Their contractions
with `bar(K)` remain on the host. The relative nugget contributes its variance
derivative; the absolute nugget has zero derivative.

The variance contraction uses Cholesky homogeneity:
`d(value)/d(sigma2) = (L:bar(L)/2 - epsilon * tr(bar(K))) / sigma2`.
Here `epsilon` is the fixed absolute nugget; it is zero for a covariance whose
nugget scales with variance. Range contractions and the homogeneity sums use
extended accumulation on the host.

This gives the Gaussian derivatives `bar(f) = -K^-1 f` and
`bar(K) = (alpha alpha' - K^-1) / 2`, with `alpha = K^-1 f`, while preserving
the noncentered forward transform and the TVC level rotation. HSGP coefficient
pullbacks use the transposed basis product, and the existing spectral-density
expressions carry scale and range derivatives.

## Gates and verification

`inst/device/benchmarks.csv` remains the sole threshold source. Dense matrix
sizes are matrix order. Temporal variants 0 and 1 are centered and noncentered
fields; variants 2 and 3 are centered and noncentered varying coefficients.
HSGP sizes are `rows * columns`, with the basis width as the exact variant.
Forward and transpose products have separate measured operations.
Rectangular cross-products use a separate operation whose exact variant pairs
the two column counts through `cross_variant`.
Unmeasured variants select CPU automatically.

`tools/bench-device-dense.R` adds runners to the shared harness. The native
timers record the first evaluation separately from steady evaluations. Steady
timings include the numerical operation, changing-input transfers, and checked
output transfers with retained workspace. The restricted NNGP runner changes
its supplied prior every evaluation. Paired trials alternate CPU/CUDA order.
Dense factor and basis fixtures use the callers' row-major storage. Basis
timings include mutable-input checks, and dense GP/spec timings include the
factor download consumed by their callers.
Equivalence checks print their reference scales and maximum absolute errors.
The dense spec ladder covers the region below the structural sparse route.

`test-device-dense.R` compares against R matrix algebra and central differences,
compares CPU/CUDA on either side of measured gates, checks signed weights, and
includes standardized long-lengthscale configurations with binding jitter.
Scale and range gradient components are checked separately from field entries.

## References

* [Cesnovar et al.](https://arxiv.org/abs/1907.01063) and
  [Stan Math's Cholesky callback](https://mc-stan.org/math/opencl_2rev_2cholesky__decompose_8hpp_source.html):
  operation-level device selection, retained matrix inputs, and reverse-mode
  matrix primitives. I copied no numerical threshold.
* [cuSOLVER](https://docs.nvidia.com/cuda/cusolver/index.html) and
  [cuBLAS](https://docs.nvidia.com/cuda/cublas/index.html): column-major layouts,
  workspace sizes, argument contracts, status handling, and the
  `potrf`/`potrs`/`trsm`/`gemv`/`gemm`/`syrk` calls.
* [Murray (2016), Section 3](https://arxiv.org/html/1602.07527v1): the symbolic
  Cholesky pullback and its expression in matrix operations. This implementation
  uses the symbolic formula expressed through BLAS matrix operations.
* [Gardner et al. (2018)](https://arxiv.org/abs/1809.11165): the matrix-free
  batched conjugate-gradient and Lanczos approach is a separate possible exact
  GP implementation. This change uses dense Cholesky throughout.
